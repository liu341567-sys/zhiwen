# 栖页 0.2.4 · 连续发布等待修复

用户在 0.2.2 验证第一条实际发布成功；第二条预览已经可播放，但没有“上传完成”提示，发布按钮因尚未填写文案而灰色，任务一直等待。本版针对该相互等待条件修复。

- 拆分“预览 / 表单就绪”和“可以提交”。填写文案不再等待发布按钮先启用，也不要求平台必须显示某个完成提示。
- 有当前视频可播放预览、简介可编辑且未检测到相关上传 / 转码进度时，进入标题与话题填写；预览可播放不会单独被当成网络上传完全结束的证据。
- 自动提交前重新检查当前上传 / 转码进度、平台发布按钮、最终文案、话题状态和素材任务归属；真实进度未结束仍不会点击发布。
- 进度判断限定在当前上传区域，排除其他作品和导航进度干扰；同时支持原生 progress 与 ARIA 进度条。
- 暂停后预览已就绪可继续同一任务，不因缺少完成提示重新上传文件。等待过程增加状态与进度日志，持续等待每约 30 秒记录一次状态。

保留 0.2.2 的逐个话题真实空格转换，不选择候选内容。原有环境 ID、账号会话与隔离、启动网址锁定、导航和品牌资产不变，任务快照保留。自动提交仍需明确授权，默认人工审阅、自定义封面 / 定位 / 平台原生定时的人工设置及提交边界防重复规则沿用。

同一原环境连续不同视频、无完成提示且按钮初始灰色、暂停继续不重复上传、真正转码阻止提交等场景由本地网页回归验证；新版真实抖音第二条发布仍需用户已登录 Windows 环境复测。不能将预览出现当作作品提交、审核通过或上线成功。

更新前正常退出旧版再安装，新版沿用原账号和任务记录。详见 [发布中心指南](https://github.com/liu341567-sys/zhiwen/blob/main/docs/publishing-guide.md)和[验证记录](https://github.com/liu341567-sys/zhiwen/blob/main/docs/validation.md)。
