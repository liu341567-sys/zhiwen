# 栖页 0.3.14 · 修复巡检时间不断后延

设置30秒巡检后，手动刷新会重启自动倒计时；若刷新结果仍异常，还会增加失败计数，按指数退避将账号重试时间推迟到几分钟甚至一小时。两种计时叠加，造成越刷新越晚的体验。

本次将手动刷新与自动巡检分开管理。自动巡检按设置的固定节奏推进；刷新一次、勾选账号、修改声音或并发等设置不再推迟既定时间。仅修改检查频率、重新开始监测会建立新的计时起点。到期时仍有检查未结束，则等待本轮结束后合并执行一次，不重叠检查、不补跑大量过期轮次。

手动刷新可以立即重查，但失败不会累加自动失败次数，也不会延长已有退避。刷新成功会清除该账号退避。只有自动检查连续失败才保留原来的单账号退避；界面明确标为“异常账号重试”，与顶部“下次自动巡检”区分。健康账号按原频率继续检查。旧版本无法区分来源的累计退避不再沿用，可靠未读基线、历史提醒、账号配置与登录数据保留。

补充连续手动刷新、跨越到期时间、休眠后恢复、暂停、频率变更、设置切换及重启恢复的调度回归，并在Windows真实窗口中等待30秒，验证连续刷新后自动轮次仍在原定时刻启动。其余品牌与页面布局、环境隔离、发布功能保持原样。

针对停留在具体对话的情况，检测到已选中对话时改用同账号独立后台列表，不再把当前聊天面板当成完整列表读取，保留原页面和草稿。另补充打开对话时的覆盖风险识别：在当前账号页发现消息输入框及发送/历史区域时显示“对话打开 · 监测受限”。官网可能将当前对话的新消息自动标为已读，未读巡检不能据此断言没有新消息。本版本只提示限制，不自动退出对话、不读取私信正文或输入草稿、不假装已经支持已读后新消息监听。诊断文件同时附带受限标志和两种计时，便于继续实页核验。

私信网页识别仍沿用0.3.13的能力边界，本次修复调度行为，不将合成网页测试视为真实账号计数验收。
