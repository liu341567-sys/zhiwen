# 栖页 0.2.2 · 抖音话题输入流程修复

针对 0.2.1 的“未识别到唯一的视频发布入口”和“页面未保留完整标题和话题”日志修复适配流程。

- 每个 `#话题` 后发送真实 Space 按键，由抖音编辑器按正常输入方式转换话题；不点击或选择候选框内容。
- 校验忽略富文本占位、零宽字符与话题节点间的渲染间距，仍逐项核对完整标题和话题。候选框未结束或内容不一致时暂停，不假装填写成功。
- 发布入口支持 SPA 的嵌套 div / span 标签，等待入口实际出现，并精确关联所识别的输入控件；作品搜索框不会被当作发布描述。
- 支持独立标题和简介输入区；上传 / 转码进度未完成时不提前填写，继续原任务上传不重复选择文件。
- 人工审阅后继续时保留已经核对的内容，不重复填写；人工确认不再消耗失败任务的五次重试限制。提交边界与防重复发布规则保留。

账号环境 ID、会话与隔离数据、启动网址锁定、Logo、导航布局、平台资产及原有业务规则沿用，无需迁移。默认仍为上传填写后人工审阅，自动提交需明确授权。自定义封面、定位及平台原生定时仍需人工设置。

本地模拟网页回归不等于真实抖音账号验收。本轮根据用户实际日志与“话题后空格自动转换”的操作反馈修复，更新后仍需在同一 Windows 环境核实上传、话题与提交结果。提交反馈只标记“已提交”，不冒充审核通过或作品上线。

更新前正常退出旧版，再安装本版；已有账号与任务记录保留。使用步骤见 [发布中心指南](https://github.com/liu341567-sys/zhiwen/blob/main/docs/publishing-guide.md)，验证结果见 [验证记录](https://github.com/liu341567-sys/zhiwen/blob/main/docs/validation.md)。
