# 智能内容发布中心 · 第一期

## 0.4.0 实时发布工作台

`renderer/publishing-workbench.js` 管理左侧账号和右侧表单，使用稳定 ID 复用 DOM，输入法组词结束后才发送更新。文案以 400 毫秒防抖发送，保留用于确认话题的尾部空格；候选按照版本更新，不因无关任务刷新而替换输入节点。原高级向导独立保留，导航与布局偏好仍由原模块维护。

`publishing/workbench.js` 将可变草稿保存到本地 SQLite setting，逐账号维护原生页面连接、独占权、修订号、上传证据及核验状态。本期每个账号只能有一条视频草稿；选择视频立即校验并上传，后续修改只同步文案。默认有限并发，同一账号与原任务调度共用执行权；准备完成的页面保留连接，巡检仅回读状态。人工接管先中止自动操作并释放连接，明确继续后才恢复。

`adapters/douyin-live.js` 直接连接原账号 WebContents，沿用真实上传、键盘及鼠标接口。页面中的所有者标记、视频路径/内容摘要、当前文案及修订号组成核验依据。官网话题候选来自实际弹层 DOM：兼容录制中的 mention-suggest/tag-hash 组件和 ARIA 列表，不将静态推荐话题视为搜索结果。节点、候选文字、输入文案或顺序变化会更换候选版本；真实点击前再次检查唯一目标及版本。候选确认后回读官网结果，尾部空格和官网非编辑标签的渲染差异单独处理。

正式确认前再次检查文件及官网实际状态，事务保存不可变批次/任务快照，并授权 `workflow: workbench` 任务。**此类任务执行只核验现有页面并点击发布，不包含导航、上传或文案填写。** 允许先确认部分已就绪账号，其余草稿保持可编辑。任务重连也只回读同一原页面；页面已丢失、归属变化或参数不一致时转人工，不恢复为旧向导流程。

正式点击前同步持久化提交边界；提交结果不明确时禁止自动重发。重启后本地草稿保留，但实时核验清除；已确认任务沿用原调度恢复规则。数据库未新增环境字段，Cookie、会话分区、启动锁定及原账号 ID 均不变。用户明确移除未提交草稿时仅清理已证明属于该草稿的编辑页面，不清理账号存储。

## 既有资源、调度与高级向导

复用 Electron 44 的 `WebContentsView`、`partitionFor(environmentId)`、CookieVault 和原账号清单。发布内容与环境唯一 ID 关联，不复制 Cookie、不新增登录系统、不改变原清单或启动锁定。

独立 `publishing.sqlite` 使用 SQLite WAL 与 FULL 同步，保存素材索引、文案资源、草稿、批次、不可变任务快照、进度和日志。素材默认只引用本地路径；缩略图与指定帧保存在本地缓存。正式执行重新验证文件内容摘要与属性。资源变更不会更新已确认的快照。

`matching.js` 负责分发、标题 / 整组话题独立匹配；0.3.10 新任务仅按顺序/单账号分发，`options.js` 编译官方日/周循环时间。旧本地计划函数仅保留兼容内部代码。`scheduler.js` 负责环境互斥、默认 2 环境并发和恢复；`adapters` 负责页面能力与提交证据。新平台只注册适配器与能力描述，不修改资源及调度机制。

抖音从用户指定作品管理入口识别发布按钮和实际表单。通过当前环境 WebContents 的调试协议定位 DOM、上传文件、填写内容，保留原会话；不启动额外浏览器进程。验证码、登录过期、页面变化和无法核实的能力转人工。网页自动化不是平台 API 的替代保证，需要实际账号验收。未核实的平台功能不能显示为自动支持。

提交前同步保存 `submitIntent`。一旦达到提交边界，中断、超时、取消或重启都进入结果待核实，不直接重试。发布成功必须具有明确作品或成功页面证据；审核、已提交与已上线分别记录。新任务确认后直接排队，官方时间具体值进入任务快照；旧任务执行计划保留，上传提交要求电脑开机联网；程序重启后错过时间五分钟以上的任务暂停等待确认。

一级导航及折叠偏好保持。发布页自己的二级选择、草稿和滚动单独保存。执行环境暂时由任务独占，人工接管先取消自动动作并等待释放，再显示原网页。关闭软件先停止自动执行，再沿用原环境存储刷新机制。

原生点击中的小区域 capturePage 只用于短时请求后台渲染，不是可点击性的判据。其未完成、空图及异常均不能替代实时 DOM 唯一性与遮挡检查；捕获不保存，暂停或销毁仍立即停止输入。真实鼠标操作后的页面状态由平台适配器验证，提交操作没有自动重试。固定阶段代码进入本地诊断，不序列化页面正文或任意错误内容。
